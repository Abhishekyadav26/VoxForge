# C1: touch targets + microcopy contrast

## Problem
Chrome text and controls below minimums: nav links 20px high, helper 2.99:1, node labels 3.32:1, back-link 19px. Findings H-3, S-5, S-6 (part), A-5. Criteria: targets ≥24px, body text ≥4.5:1.

## Options considered
| Option | Idea | Weighted score (Usab / Visual / Eng) |
|--------|------|--------------------------------------|
| A Minimal | global CSS floor in globals.css | 20 / 18 / 23 |
| B Restructure | SiteNav/ComposerBar/HelperText components | 21 / 22 / 15 |
| C Convention | shadcn Button sm + text-sm contract | 22 / 23 / 19 |

Lens detail (criterion order 1–6, weights ×3 ×2 ×2 ×2 ×2 ×1):
- Usability pass: A 4/3/3/4/3/5=42; B 4/4/4/4/4/3=46; C 5/4/5/5/4/4=54.
- Visual pass: A 4/3/3/3/3/5=41; B 4/4/5/4/4/3=47; C 5/4/5/4/5/4=54.
- Engineering pass: A 5/3/3/3/3/5=44; B 4/4/4/4/4/2=44; C 5/4/4/4/4/4=52.
Totals: A 127 · B 137 · C 160.

## Decision
**C with an A graft**: use `Button size="sm"` (h-8) for header/composer/back-link chrome and `text-sm`+lighter-slate for helpers; graft A's one-line `.react-flow__node` label-color override and the global `min-height:24px` floor for raw links.

## Why this is the best
- Against A: CSS-only fixes sizes but leaves ad-hoc classes — the next contributor reintroduces 20px links; C puts the contract in the component.
- Against B: three new components for a 4px bump is over-engineering; C reuses the existing button system.
- Norms: I4, A1, H5. Costs: header grows ~12px; rules out nothing.

## Implementation plan
1. `components/ui/button.tsx` — verify sm = h-8; add `min-h` guarantee.
2. `app/layout.tsx` — nav links + AuthButton via Button sm asChild.
3. `app/studio/page.tsx` — chips py-2, helper text-slate-300.
4. `app/globals.css` — react-flow node label color override + raw-link min-height floor.
5. `app/agents/[id]/page.tsx` — back link to Button ghost sm.

## Test plan
Layout assertions: nav link heights ≥24; helper contrast ≥4.5 (computed); chips ≥32px. Viewports 1440/390. e2e: none (visual only).
