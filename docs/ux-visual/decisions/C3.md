# C3: register error + auth hierarchy

## Problem
Empty-name register shows raw Zod JSON (L-1, reproduced live); equal-weight auth buttons (L-2). Criteria: human error message; primary/secondary split.

## Options considered
| Option | Idea | Scores |
|--------|------|--------|
| A Minimal | error map only | 40 / 36 / 50 = 126 |
| B Restructure | inline field errors + demote Google | 52 / 48 / 44 = 144 |
| C Convention | Linear-style auth card | 50 / 52 / 38 = 140 |

## Decision
**B**: per-field inline errors with `aria-describedby`, server Zod mapped to field messages; Google stays below the divider at default (not lg) weight; email submit is the sole lg primary. Toasts reserved for non-field failures.

## Why this is the best
- Against A: A fixes the reported string but leaves the next Zod error raw; B maps all field errors once.
- Against C: full card restyle churns a working page for little gain; B keeps layout, fixes behavior.
- Norms: I3, C1, H1. Costs: login file only; rules out nothing.

## Implementation plan
1. `app/login/page.tsx` — field-error state, inline messages, button weights.
2. Register route error shape — pass field errors through.

## Test plan
Register with empty name → "Please enter your name" under the field (e2e); Google button is outline-default; email submit is the only lg.
