# C4: studio next-action guidance

## Problem
Five equal-emphasis chips; the next step doesn't stand out (S-1). Criterion: exactly one primary per thread state.

## Options considered
| Option | Idea | Scores |
|--------|------|--------|
| A Minimal | state-driven primary chip | 50 / 44 / 52 = 146 |
| B Restructure | stepper + single action | 52 / 50 / 38 = 140 |
| C Convention | inline CTAs in bubbles | 48 / 50 / 40 = 138 |

## Decision
**A now, C's direction noted**: compute next action from thread state and fill that chip white; keep all chips (voice discoverability — users must see the command words). Revisit inline bubble CTAs after voice-command analytics exist.

## Why this is the best
- Against B: stepper adds a state machine users must learn; chips already teach the voice commands — A preserves that.
- Against C: removing chips hides the voice vocabulary; A keeps it while adding guidance.
- Norms: H1, H2, I6. Costs: ~10 lines in studio page; rules out nothing.

## Implementation plan
1. `app/studio/page.tsx` — `nextAction` derived from spec/trace/deploy state; primary style on that chip.

## Test plan
Empty → generate primary; spec → trace primary; traced → deploy primary (snapshot/e2e at 1440/390).
